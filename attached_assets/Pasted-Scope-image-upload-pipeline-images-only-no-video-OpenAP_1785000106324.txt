Scope: image upload pipeline (images only — no video). OpenAPI-first. Do not modify reactions, the feed pager's gestures, auth, or nav.

API — POST /uploads/presign: authenticated; body: contentType (must be image/jpeg, image/png, or image/webp) and sizeBytes (must be ≤ 10MB) — reject others with structured 400s. Returns { uploadUrl, mediaKey } where uploadUrl is a short-expiry presigned PUT to the R2 bucket using the R2_ACCOUNT_ID/R2_ACCESS_KEY_ID/R2_SECRET_ACCESS_KEY/R2_BUCKET_NAME secrets (S3-compatible endpoint https://<accountid>.r2.cloudflarestorage.com, via @aws-sdk/client-s3 + @aws-sdk/s3-request-presigner). mediaKey pattern: posts/<uuid>.<ext>.
API — POST /posts: authenticated; body: petId, mediaKey, optional caption, isNursery (default false). 403 if the pet isn't owned by the caller. Creates the post.
Media serving: feed and pet responses add mediaUrl per post — a presigned GET URL (≥1 hour expiry) generated server-side for R2 keys. Posts with seed: keys keep the existing local-asset bridge unchanged.
Mobile — the Add tab becomes real: if the user owns no pets, show a prompt linking to pet creation. Otherwise: pick an image (expo-image-picker), client-side downscale/compress to max 2048px longest edge as JPEG before upload (expo-image-manipulator on native; equivalent canvas-based approach on web if the lib doesn't cover it), preview + caption field + Nursery toggle + pet selector (preselected if only one pet). Flow: presign → PUT the compressed image → POST /posts → on success navigate Home, invalidate the feed query so the new post appears at the top. Friendly rejection copy for oversized/unsupported files.
Apply identically to web, iOS, and Android. No react-native-reanimated imports.

Acceptance test: On a physical iPhone: pick a photo from the camera roll, add a caption, post — it appears at the top of the swipe feed and renders on web and Android too, alongside Finn's seeded posts.
