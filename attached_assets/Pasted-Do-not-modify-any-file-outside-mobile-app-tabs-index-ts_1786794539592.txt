CONTEXT: A confirmed investigation traced a rapid-scroll bug on the Home feed to mid-momentum page appends during pagination. When onEndReached fires while the user is actively scrolling, new posts get appended to the FlatList's data, which mutates the DOM (new cells inserted, content-container height grows) while the browser's mandatory CSS scroll-snap (from pagingEnabled) is still active. Per the CSS scroll-snap spec, browsers re-evaluate and re-snap after in-scroller content changes — so a mid-momentum append can cut the user's scroll short and re-commit to a different snap position, producing the rapid multi-post jump. This is a sibling of the Aug 12 windowHeight-triggered bug (same failure class, different trigger) — the Aug 12 debounce fix does NOT cover this path and is confirmed uninvolved.

FIX 1 — suppress scroll-snap during a page append (index.tsx):
The codebase already has a proven pattern for temporarily suppressing scroll-snap during a programmatic update (used in the web restore-on-close and viewport re-anchor logic — search for where `scrollSnapType` is set to 'none' and restored). Apply the same technique around the page-append moment: when a new page of posts is about to be appended to the flattened posts memo (i.e., right before/during the fetchNextPage → data update → re-render cycle), suppress scroll-snap on the scroller node, let the DOM update settle (e.g. via requestAnimationFrame, consistent with the existing pattern's timing approach), then restore scroll-snap. This should be scoped ONLY to the page-append case — do not touch or interfere with the existing windowHeight re-anchor or comment-sheet restore suppression logic, which are separate and already working correctly.

FIX 2 — memoize FeedPage (FeedPage.tsx):
FeedPage is currently exported as a plain function component with no memoization, so every re-render of the parent (including on every page append) re-renders ALL currently-mounted FeedPage cells, not just newly added ones. Wrap the component in React.memo with an appropriate comparison (default shallow-prop comparison should suffice given props are post, height, reducedMotion, onOpenCommentSheet — verify these are stable/appropriately memoized at the call site in index.tsx, and if any prop is being passed as a new reference on every render, e.g. an inline arrow function, fix that at the call site so React.memo is actually effective). Do not change any of FeedPage's internal rendering logic, only wrap it for memoization and ensure its props are stable.
