SCHEMA (users table, additive columns only — no changes to existing columns):
- username: text, nullable for now, UNIQUE case-insensitively (store
  lowercase; add a unique index on lower(username))
- display_name: text, nullable
- location_city: text, nullable
- about: text, nullable

API:
- GET /users/me returns the new fields.
- PATCH /users/me accepts them, merge semantics (only provided fields
  change), with ALL validation server-side:
  - username: lowercase before validating/storing; must match
    ^[a-z][a-z0-9._]{2,19}$ (3–20 chars, starts with a letter; letters,
    numbers, period, underscore only); no consecutive or trailing "." or
    "_"; rejected if on the reserved list: admin, administrator, mod,
    moderator, staff, support, help, official, root, system, pshpsh,
    pshpshapp, petpal, petpalnetwork; rejected with a clear "taken"
    error if the lowercase value collides with an existing user.
  - display_name: 1–40 chars, trimmed.
  - location_city: 0–60 chars, trimmed, plain text.
  - about: 0–200 chars, trimmed.
- Client never enforces alone — server is the authority.
