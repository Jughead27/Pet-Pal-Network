CONTEXT: Two compounding, now-confirmed defects in the Sniff pager's web scroll-correction logic (via instrumented repro with real numbers):
1. The verify-and-correct loop's "expected offset" check has a false-match bug: if the target post isn't yet resolvable in the data at check time, findIndex returns -1, which the loop treats as index 0 — producing an "expected offset" of 0 that trivially matches the actual scrollTop of 0 at mount. The loop declares success and stops watching, for the WRONG target.
2. Separately, on web, pagingEnabled compiles to mandatory CSS scroll-snap. If a later correction moves the scroll into a region whose cells aren't yet committed (not a valid snap point), the browser's mandatory snap re-snaps back toward the nearest already-rendered cell edge — silently undoing a correction that briefly succeeded.
Together these explain why only the first ~2 grid positions (which sit inside the pager's default, always-valid initial render window) work — everything beyond it depends on winning a race between data resolution and the browser's snap behavior, and currently loses.
