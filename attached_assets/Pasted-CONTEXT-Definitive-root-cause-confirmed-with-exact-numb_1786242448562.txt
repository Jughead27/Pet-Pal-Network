CONTEXT: Definitive root cause confirmed with exact numbers. The feed post frame is currently positioned by centering it independently on screen: `frame.top = (containerHeight - frameHeight) / 2`. Separately, when a post's chrome (name/caption) needs to sit below the frame, it's positioned at `frame.bottom + 14`, clamped to never go below `containerHeight - bottomOffset - chromeHeight`. These two rules conflict for any centered square/portrait frame shorter than ~288px — since a 1:1 frame is 390px and 4:5 is 488px on a typical viewport, EVERY centered 1:1/4:5 frame guarantees this conflict, causing chrome to overlap the photo (clamp wins over the true 14px-below position).

GOAL: Stop centering the frame independently. When a post's chrome needs to sit below the frame (i.e. the frame is not vertically full-bleed), treat [frame + 14px gap + chrome] as a single unit and position that whole unit anchored against the bottom constraint (bottomOffset), rather than centering the frame alone and then trying to fit chrome into whatever space remains below it.

Specifically:
1. Compute chrome height (petInfoH) and the required gap (14px) as already established.
2. Compute the total stack height needed: frameHeight + 14 + chromeHeight.
3. Anchor this stack so chrome's bottom edge sits at exactly `containerHeight - bottomOffset` (never lower, never needing a clamp override) — meaning frame.top = `containerHeight - bottomOffset - chromeHeight - 14 - frameHeight`.
4. This will generally rise the frame ABOVE the old centered position for short frames (e.g. 1:1 rises from top=227 to roughly top=176-190 for a 390px frame in the numbers already computed) — that's expected and correct, not a bug.
5. For frames where chrome stays overlaid ON the photo (vertically full-bleed posts), this change does not apply — keep the existing centering/positioning for those, unchanged.
6. The old clamp-based fallback logic (from this morning's fix) should no longer be needed for the below-frame case once frames are positioned this way — remove it if it's now dead code, but confirm nothing else depends on it first.

DO NOT MODIFY:
