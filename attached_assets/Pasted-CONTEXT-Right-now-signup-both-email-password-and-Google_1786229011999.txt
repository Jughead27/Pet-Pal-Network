CONTEXT: Right now, signup (both email/password and Google OAuth) requires no name at all — accounts are only identified internally by an auto-generated username (an email prefix, e.g. "james.guilfoyle2"). displayName exists in the schema but is optional and only set later via manual profile edit, so most users never set one — they show up everywhere in the app as an anonymous "ghost" with no real identity.

GOAL: Make displayName a REQUIRED field collected directly on the signup form, for both signup paths.
1. Add a "what should we call you?" (or similar) text field to the email/password signup form, alongside email and password. Blank by default — no pre-fill.
2. For Google OAuth signup: do NOT pre-fill this field from Clerk's Google profile data, even though that name is technically available — the user must type/choose it themselves, same as the email/password path. If OAuth flow doesn't naturally have a form step to insert this into, add one (e.g. a single required field shown immediately after OAuth completes but before the account is considered fully set up).
3. This field should save to the existing displayName column — do not create a new field.
4. Validation: required (non-empty), reasonable max length, no uniqueness constraint needed (username already serves as the internal unique key).
5. Existing users who already have a displayName set are unaffected. Existing users WITHOUT one are also out of scope for this prompt (no retroactive prompt/migration) — this only affects new signups going forward.

DO NOT MODIFY:
- The username generation logic — stays as internal, invisible plumbing, unaffected by this change.
- Any other part of the signup flow (ToS consent, email verification, invite redemption) — all already working, untouched.
- The profile-edit screen where displayName can already be changed later — unaffected, still works the same way after initial signup.

PRESERVATION CLAUSE: Do not touch unrelated files. This is additive — one new required field on signup, using the existing displayName column.

ACCEPTANCE TEST (must end in golden path):
1. Start email/password signup — confirm a required "what should we call you?" field appears, blank, and signup cannot complete without filling it in.
2. Start Google OAuth signup — confirm the same required field appears, still blank (NOT pre-filled from Google's name data), and OAuth signup cannot complete without it either.
3. Complete a signup via each path with a chosen name — confirm the account's displayName is saved correctly and appears correctly wherever displayName is shown elsewhere in the app (e.g. co-ownership modals, comments).
4. Confirm an EXISTING user with no displayName set is unaffected by this change (not forced to set one retroactively, no broken state).
5. Golden path: start signup → attempt to submit without a name (blocked) → enter a name → complete signup → confirm the chosen name displays correctly in-app → sign out. Verified live on pshpsh.net.
