CONTEXT: The species chips (Sniff and Nursery) and the breed dropdown (Sniff) currently derive their options by sampling the 50 most recent posts and seeing what species/breeds appear in that sample. This means a species or breed with real posts can be invisible to the picker if its only post(s) fall outside the 50 most recent — undermining discovery, which is the actual purpose of these screens. This needs to be replaced with a precise query, not a sample.

FIX — add two new lightweight, read-only endpoints (or one endpoint with a mode, whichever fits this codebase's conventions better):
1. "Species with posts": returns the distinct set of species that have at least one eligible post (respecting whatever eligibility rules the main feed query already applies — excluding archived/hidden/blocked posts, same as today). Should support an optional isNursery filter, since Nursery needs this scoped to nursery posts specifically.
2. "Breeds with posts for a species": given a speciesId, returns the distinct set of breeds (matched against the catalogue, same exact server-resolved breed-name matching already used in the current implementation) that have at least one eligible post for that species.

Both should be efficient distinct/grouped queries against the posts table (e.g. SELECT DISTINCT species_id ... or a GROUP BY), not a fetch-and-filter-in-application-code approach, and not bounded by any post-count sample — the whole point is these must be exhaustive, not a sample.
